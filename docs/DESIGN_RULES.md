# ReadySignal Design Rules

## Philosophy

ReadySignal exists to prepare SDRs for conversations.

Every screen should reduce thinking, not increase it.

## Principles

- The homepage is a queue, not a dashboard.
- Every recommendation should be understood in under five seconds.
- Expand details only when requested.
- Keep users moving toward the next conversation.
- Trust is more important than information density.
- Integrate into existing workflows instead of replacing them.

Every new feature must reduce the time between opening ReadySignal and making the first high-quality call.

If a feature slows the SDR down, it doesn't belong in the core product.
